# VERAPEP V14.1 — Operational hardening

Date: 12 August 2026

V14.1 completes additional application-side work that can be done safely before external production accounts and legal/commercial decisions exist.

## Implemented

### Per-admin MFA
- Every admin account can enroll its own TOTP authenticator.
- Enrollment requires a live 6-digit verification before activation.
- Eight one-time recovery codes are issued after enrollment.
- Recovery codes are stored only as SHA-256 hashes and are consumed after one successful use.
- Production readiness requires all enabled `owner` and `admin` accounts to have per-user MFA.
- A bootstrap `ADMIN_TOTP_SECRET` can still be used by the owner to enter production for initial enrollment, but it does not satisfy final readiness.
- `MFA_ENCRYPTION_KEY` encrypts TOTP seeds at rest using AES-256-GCM. Production readiness requires a 32+ character key.

### Operational order queues
Admin now exposes explicit queues for:
- awaiting payment
- to pack
- ready to ship
- in transit
- completed
- needs attention

The queue counts are derived server-side from payment and fulfilment state, keeping those concepts separate.

### Privacy request export
Owner/admin users can generate a read-only customer-data export by email. The export contains matching customer records, orders, returns, withdrawal notices and stored transactional messages. The action is audit logged. It deliberately does not delete or mutate accounting/order records because retention/deletion rules still require a legal/business decision.

### Transactional email retry tooling
`npm run email:retry` can retry failed email-webhook deliveries. Safety controls:
- requires `EMAIL_DELIVERY_MODE=webhook`
- requires `EMAIL_WEBHOOK_URL`
- requires exact `EMAIL_RETRY_ACK=I_UNDERSTAND_THIS_RETRIES_TRANSACTIONAL_EMAIL`
- retries failed messages by default
- sends an idempotency key derived from the original message ID
- rewrites delivery status/retry count in the outbox record

Stored preview messages are not retried unless `EMAIL_RETRY_INCLUDE_STORED=true` is deliberately set.

### PostgreSQL target updated
`sql/postgres-schema.sql` now includes per-admin MFA state and recovery-code storage fields so the managed Postgres migration does not regress the V14.1 security model.
